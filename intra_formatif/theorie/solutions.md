## 1. À quoi sert la commande git status?

Elle sert à voir l'état des fichiers locaux, donc quels nouveaux fichiers seront ajoutés au prochain commit.

## 2. Quel est l'avantage d'utiliser .map avec une collection de composantes?

C'est une bonne façon d'éviter d'avoir à utiliser des indices et tout traiter de la même manière.

## 3. Qu'est-ce que la déstructuration d'un objet?

C'est une réassignation explicite des variables, qui enlève aussi la structure d'objet (déstructuration).

## 4. Si on est sur la branche master, est-ce qu'on a utilisé git clone? Pourquoi?

Non, on a probablement utilisé git init, car les branches par défaut de Git sont nommées main.

## 5. Pourquoi utilise-t-on <> ... </> autour des balises jsx dans App.jsx?

Pour renvoyer une seule balise. La balise vide contient toutes les autres et est leur parent.

## 6. Pourquoi voudrait-on garder le code CSS des footers dans Footer.css? 

Si on décide de modifier le Footer, on a dans ce fichier uniquement ce qui concerne le Footer, ce qui facilite la maintenance.

## 7. À quoi sert la commande .filter() en javascript?

Elle sert à conserver seulement les données d'un tableau ou d'un objet qui satisfont la condition dans le filtre.

## 8. Quelle est l'utilité de passer des objets JS en props?

L'idée est d'envoyer des données structurées, découpées en attributs, pour bien placer chaque valeur au bon endroit de manière propre.

## 9. Est-il vrai qu'il faut push après chaque commit? Que se passe-t-il sinon?

Non, ce n'est pas absolument nécessaire. 
Si ce n'est pas fait, on a plusieurs commits qui restent sur notre ordinateur et ne sont pas envoyés à GitHub.

## 10. Si git push échoue avec un message de conflit, quelle commande devrait-on faire?

On devrait faire git pull afin de mettre notre version à jour avec le remote.
